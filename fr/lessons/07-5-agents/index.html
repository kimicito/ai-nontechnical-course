07.5 Scénarios d'agents

⏱ 12 min · suivi des marchandises, routes, réclamations
En quoi un agent diffère d'un modèle de langage ?
Un LLM répond aux questions. Un agent travaille en continu : suit les marchandises, analyse les retards, avertit — sans commande « où est ma marchandise ? ». Plus de détails — Niveau 4.

Scénario 1 : Agent de suivi des marchandises (n8n + API TMS)

Tâche : suivre les statuts des marchandises, avertir des retards, mettre à jour les clients.

[Cron: toutes les 30 min]
↓
[API TMS / transporteur: statuts des voyages actifs]
↓
[Agent: analyse des écarts]
├─→ Marchandise en route plus longtemps que la norme: alerte
├─→ Statut non mis à jour >24h: demande au transporteur
└─→ Marchandise arrivée: notification au client
↓
[Notifications automatiques]
├─ Client: «Marchandise arrivée au point X, livraison demain»
├─ Logisticien: «Voyage N retardé de 2 jours, cause: [API]»
└─ Entrepôt: «Planifiez la réception pour [date]»
↓
[Tableau de bord quotidien: tous les voyages, statuts, risques]
Résultat : les clients apprennent les retards avant d'appeler. Économie de 20–30 appels par jour.

Scénario 2 : Agent d'optimisation des routes (agent OpenClaw)

Tâche : analyser les données historiques de routes, proposer des alternatives, évaluer les coûts.

[Demande: «Оптимизировать маршрут Москва → Новосибирск»]
↓
[Agent: сбор данных]
├─→ Исторические маршруты (время, стоимость, инциденты)
├─→ Текущие тарифы перевозчиков
├─→ Пограничные условия (очереди, погода)
└─→ Требования клиента (срок, температура)
↓
[On-prem LLM: сравнительный анализ]
├─→ Вариант А: ЖД, срок, стоимость, риски
├─→ Вариант Б: Авто, срок, стоимость, риски
└─→ Вариант В: Мультимодальный, срок, стоимость, риски
↓
[Рекомендация с обоснованием]
├─ Оптимальный по цене
├─ Оптимальный по сроку
└─ Оптимальный по риску
↓
[Отчёт логисту]

Scénario 3 : Agent de réclamations aux transporteurs (hybride)

Tâche : collecter les données sur retards et dommages, préparer des réclamations, suivre les délais de réponse.

[Триггер: статус рейса = «доставлен»]
↓
[Agent: сбор данных]
├─→ Плановая vs фактическая дата доставки
├─→ Акты осмотра (повреждения)
├─→ Трекинг: фактический маршрут
└─→ Переписка с перевозчиком
↓
[On-prem LLM: оценка оснований для претензии]
├─→ Задержка > допустимой: расчёт штрафа
├─→ Повреждение: оценка по акту
└─→ Недостача: сверка по накладной
↓
[Автоматическая генерация претензии]
├─→ Ссылки на договор, пункты
├─→ Расчёт суммы требования
└─→ Срок для ответа
↓
[Отправка перевозчику + создание задачи в СЭД]
↓
[Мониторинг: ответ не получен в срок → эскалация]
Important : les réclamations contiennent des informations commerciales (montants, conditions contractuelles). Tout le traitement — on-prem.
