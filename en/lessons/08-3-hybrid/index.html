8.3 Hybrid Tasks: De-identification

15 min · for procurement specialists · boundary of perimeters

Some tasks sit on the boundary: they can be done in the cloud, but only if the data is de-identified. Replace the supplier name with "Supplier A", remove specific prices — and the task becomes safe for an external model.

This lesson covers how to de-identify data, which tasks are acceptable in hybrid mode, and how to prepare a request for developers for automation.

The Rule: De-identify Before the Cloud

What CANNOT be sent to the cloud (even partially):
  • Specific prices from quotations
  • Supplier names (unless they are giants like Siemens)
  • Purchase volumes for specific items
  • Contract terms (penalties, discounts, deferrals)
  • Negotiation position, BATNA, supplier weak points
What CAN be sent after de-identification:
  • Comparison of quotation structure (without prices) — "Supplier A vs Supplier B"
  • Analysis of response completeness to TS (without names)
  • Role-play negotiation rehearsal (anonymous scenario)
  • Compilation of general arguments (without specific numbers)

De-identification Checklist (5 Steps)

  1. Replace names: "LLC PromTekhSnab" → "Supplier A"
  2. Replace prices with relative ones: "1,200,000 ₽" → "base price +20%" or "Price X"
  3. Remove volumes: "50 units" → "medium-sized batch"
  4. Remove contract dates: "until 31.12.2025" → "contract until year-end"
  5. Check: if you show the de-identified text to a colleague — will they understand what it's about but not know the supplier? If yes — it can go to the cloud.

1. Role-Play Negotiation Rehearsal

A procurement specialist is preparing for difficult negotiations. Need to run through a scenario. You can de-identify the data and use a cloud model as the "opponent."

Prompt example (de-identified)
Проведи со мной ролевую репетицию переговоров.

Сценарий (обезличенный):
- Я закупщик в промышленной компании
- Мне нужно снизить цену на поставку оборудования
- У меня есть 2 альтернативных поставщика с ценой на 15% ниже
- Текущий поставщик (Поставщик А) задержал поставку в прошлый раз
- Мне нужен срок 3 недели, у него стандартно 6 недель
- Я готов обсуждать объём, но не раскрывать конкретные цифры

Ты играешь роль Поставщика А. Твоя цель — удержать цену и сроки.
Моя цель — снизить цену и ускорить срок.

Начни переговоры. Отвечай как реальный поставщик — 
с возражениями, контраргументами, попытками уйти от темы.
Result: 15–20 minutes of rehearsal with a "live" opponent. The procurement specialist practices arguments, learns to deflect objections, and prepares for the real conversation.

2. Quotation Structure Comparison (Without Prices)

You need to understand which supplier responded to the TS more fully, not who is cheaper. Prices are removed; only structure and completeness are compared.

Prompt example (de-identified)
Сравни 3 коммерческих предложения по структуре и полноте ответа.

Данные обезличены:
- Поставщик А, Поставщик Б, Поставщик В
- Цены удалены, только относительные: "ниже рынка", "рынок", "выше рынка"

Сравни по критериям:
1. Полнота ответа на ТЗ (все ли пункты покрыты)
2. Наличие технических описаний (да/нет, качество)
3. Наличие сертификатов (перечень)
4. Условия гарантии (сроки, объём)
5. Дополнительные услуги (монтаж, обучение, сервис)

Не называй конкретные цены. Дай рекомендацию по полноте.

3. Compilation of General Arguments

A procurement specialist needs a list of arguments for negotiations in general form — not tied to a specific deal. A cloud model generates the base, then on-premise adds specifics.

Prompt example (de-identified)
Я готовлюсь к переговорам по закупке промышленного оборудования.

Контекст (обезличенный):
- Рынок: 3–4 крупных поставщика, конкуренция высокая
- Моя позиция: крупный заказчик, регулярные закупки
- Проблема: поставщик хочет повысить цену и сроки

Подготовь общие аргументы для переговоров:
1. Аргументы для снижения цены (рынок, объёмы, конкуренция)
2. Аргументы для ускорения сроков (планирование, резервы, штрафы)
3. Контраргументы на типичные возражения поставщиков
4. Вежливые формулировки для твёрдой позиции

Без конкретных цен, названий, объёмов. 
Только шаблоны, которые я потом адаптирую.

Request to Developers for De-identification Automation

If procurement specialists frequently de-identify documents manually — this can be automated. Here is a template request for the IT team.

Developer request template
Задача: создать скрипт/приложение для обезличивания 
закупочных документов перед отправкой в облачные LLM.

Вход: файл (PDF, Word, Excel) с коммерческим предложением.
Выход: тот же файл с заменёнными данными.

Правила замены:
1. Названия компаний → "Поставщик А", "Поставщик Б" и т.д.
2. Суммы → относительные ("базовая цена", "+15%", "-20%")
3. Объёмы → "партия малого/среднего/крупного размера"
4. Даты → относительные ("в текущем квартале", "до конца года")
5. Контактные данные → удалить полностью
6. Номера договоров → "Договор N"

Дополнительно: проверка — что в выходном файле 
не осталось оригинальных данных (поиск по ключевым словам).

Интеграция: drag-and-drop файл → получить обезличенную версию 
за 5 секунд. Сохранение истории обезличиваний.

Приоритет: высокий (используется ежедневно 5–10 закупщиками).
💡 Tip: even if IT cannot build a full application, you can start with a simple Python script. It will replace 80% of manual work. Then improve it.

Knowledge Check

Question 1: Which of these CANNOT be sent to the cloud even after de-identification?

Supplier name → "Supplier A"
Specific penalty clauses from an active contract
"Price above market by 10%"

Question 2: What is the first step of the de-identification checklist?

Remove all dates
Replace company names with "Supplier A", "Supplier B"
Remove all numbers from the document

Question 3: How do you check if a document is de-identified enough?

Send it to the cloud and see if the system blocks it
Show it to a colleague — do they understand the gist but not know the supplier?
Remove all numbers and names — that's enough

Question 4: Which task from the list is hybrid (de-identification + cloud)?

Checking a contract against a template for deviations
Role-play negotiation rehearsal with an anonymous scenario
Searching for new suppliers on the internet

Question 5: What should you do if procurement specialists constantly de-identify documents manually?

Prepare a request to developers for script-based automation
Continue manually — it's more reliable
Send originals to the cloud — it's faster
