Level 8 — Procurement

8.2 External Tasks: Cloud

15 min · for procurement specialists · open data

This lesson covers tasks where a procurement specialist works with public information: searching for suppliers, benchmarking prices, preparing de-identified documents. This data does not contain trade secrets — it can be sent to cloud-based models.

Solution: cloud APIs: Claude, ChatGPT, Kimi, Qwen API. If web search is needed — the model must be connected to the internet.

When Cloud is Better Than On-Premise

Cloud models win when you need:
  • Web search: find new suppliers, check market prices
  • Translation: work with foreign documents
  • Generation: create a template text from scratch
  • Public data analysis: commodity indices, exchange rates, customs codes
Important: before sending to the cloud — check that the request contains no specific prices, supplier names, or volumes. If it does — de-identify or send to on-premise.

1. Finding Analogs and Alternative Suppliers

A procurement specialist knows 2–3 suppliers for a position. Need to find more — for competition or backup. On-premise has no internet access; the cloud does.

Prompt example (Claude with web search)
Найди производителей промышленных центробежных насосов 
серии 32-160 в России и ближнем зарубежье (Казахстан, Беларусь).

Укажи:
- Название компании и сайт
- Где производство (город)
- Есть ли сертификаты (ГОСТ, ISO)
- Примерный диапазон цен (если публично)
- Контакты для закупок (отдел продаж)

Сделай таблицу сравнения.
Result: table of potential suppliers with contacts. The procurement specialist spends 10 minutes instead of 2 hours of manual searching.

2. Market Price and Commodity Index Benchmarking

A procurement specialist negotiates a price but doesn't know where the market is. An LLM with web search finds current indices.

Prompt example
Какие сейчас (2024-2025) рыночные цены на:
1. Стальную арматуру А500С (опт, тонна)
2. Портландцемент М500 (опт, тонна)
3. Медь катодную (LME + премия)

Также укажи:
- Динамику за последние 6 месяцев (рост/падение %)
- Прогноз на ближайший квартал (если есть)
- Основные факторы, влияющие на цену
Important: the request does not contain specific prices from your suppliers — only market benchmarks. This is safe for the cloud.

3. Preparing a De-identified Technical Specification (Draft)

A TS with specific numbers — goes to on-premise. But a draft structure of the TS, general requirements, typical parameters — can be done in the cloud, then finalized internally.

Prompt example
Подготовь структуру технического задания на закупку 
промышленного насосного оборудования для химического производства.

Без конкретных цифр (объёмов, цен, сроков). 
Только типовые параметры и требования.

Структура:
1. Общие требования
2. Технические параметры (мощность, производительность, материалы)
3. Требования к качеству и сертификации
4. Условия поставки (типовые)
5. Требования к документации
6. Критерии приёмки

Укажи, какие пункты нужно будет дополнить конкретными данными внутри компании.

4. Tender Documentation (General Sections)

Instructions for participants, evaluation criteria, application form — all of this is template-based and does not contain data from a specific deal.

Prompt example
Создай шаблон тендерной документации для закупки 
промышленного оборудования методом открытого конкурса.

Включи:
1. Инструкция для участников (правила подачи, сроки)
2. Форма заявки (общие поля)
3. Критерии оценки (цена, сроки, опыт) — без весовых коэффициентов
4. Форма договора (типовые условия)
5. Перечень документов для заявки

Укажи, какие разделы нужно согласовать с юристом и заказчиком.

5. Auto-Responses to Clients and Platforms

Shipment status, delivery times, quotation requests — often template-based. An LLM generates a response based on ERP status but without specific numbers.

Prompt example
Напиши шаблон письма ответа на запрос статуса поставки.

Условия:
- Заказ в пути
- Поставщик сообщил о задержке
- Нужно извиниться, объяснить причину, назвать новый срок
- Предложить компенсацию (типовая)

Без конкретных дат, сумм, названий поставщиков. 
Получатель: заказчик внутри компании.

6. Document Translation and Localization

Foreign suppliers send instructions, specifications, and contracts in English, Chinese, or German. Cloud translation is faster and more accurate than standard translators for technical texts.

Prompt example
Переведи с английского на русский техническую спецификацию 
на промышленный насос (файл Spec.pdf).

Требования:
- Сохрани структуру и нумерацию разделов
- Технические термины — по ГОСТ/ISO
- Единицы измерения — в СИ (м³/ч, бар, кВт)
- Сохрани таблицы в формате markdown
- Отметь непонятные места для уточнения у поставщика

7. Customs Requirements Check (General Regulations)

HS code, certification requirements, duties — this is public information. An LLM finds current requirements for a product category.

Prompt example
Какие таможенные требования и сертификаты нужны 
для ввоза в РФ промышленных центробежных насосов (код ТН ВЭД 8413 70)?

Укажи:
- Обязательная сертификация (ГОСТ-Р, ТР ТС)
- Нужен ли СБКТС
- Таможенная пошлина (ставка)
- НДС при ввозе
- Требования к документам поставщика (инвойс, упаковочный лист)
- Особенности для конкретных стран (КНР, Германия, Италия)

Без конкретного груза и сумм — только общая нормативка.

Knowledge Check

Question 1: Why is searching for new suppliers better done in the cloud than on-premise?

Because on-premise has no internet access for searching
Because on-premise works slower
Because the cloud is free

Question 2: Which model should NOT be used for price benchmarking?

Claude with web search
On-premise LLM without internet
ChatGPT with browsing

Question 3: Which request is safe for the cloud?

"Compare prices of my 3 suppliers: A, B, C" (with specific amounts)
"What are the market prices for rebar A500C in 2025?"
"Check the contract with supplier X against the template"

Question 4: Which task can be done in the cloud if the TS contains specific volumes?

Send the full TS with volumes to ChatGPT
Create a draft TS structure without numbers, then add volumes on-premise
You cannot use AI for a TS at all

Question 5: Which model is best for translating technical specifications?

Claude or GPT-4 — they handle technical terms better
Any free model — translation is a simple task
Only on-premise model, because specifications may contain prices
