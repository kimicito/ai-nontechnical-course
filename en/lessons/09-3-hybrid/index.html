9.3 Hybrid Tasks: De-identification

15 min · for construction specialists · boundary of perimeters

Some construction tasks sit on the boundary between on-premise and cloud. They can be done in the cloud, but only if the data is de-identified. Replace the facility address with "Object A", remove specific contract amounts — and the task becomes safe for an external model.

This lesson covers how to de-identify construction data, which tasks are acceptable in hybrid mode, and how to prepare a request for automation.

The Rule: De-identify Before the Cloud

What CANNOT be sent to the cloud (even partially):
  • Specific contract amounts and estimate totals
  • Contractor names (unless they are major market players)
  • Geodetic coordinates and exact addresses
  • Subcontract terms (penalties, bonuses, deferrals)
  • Work completion certificates with actual volumes
  • Photos showing security zones or strategic objects
What CAN be sent after de-identification:
  • General construction technology questions
  • Structural element checks without specific dimensions
  • Standard specification templates
  • Textual concept descriptions without prices
  • General regulatory compliance checks

De-identification Checklist for Construction (5 Steps)

  1. Replace facility names: "Office Center, Building A, Moscow" → "Object A"
  2. Remove specific amounts: "15,000,000 ₽" → "contract amount X" or "base amount +20%"
  3. Remove geodetic data: coordinates, exact addresses, elevation marks
  4. Replace contractor names: "LLC StroyMontazh" → "Contractor A"
  5. Check: if you show the de-identified text to a colleague — will they understand what it's about but not know the facility or contractor? If yes — it can go to the cloud.

1. De-identified Equipment Search

Need to find an analog for a failed pump but can't share the facility details. De-identify the parameters and search in the cloud.

Prompt example (de-identified)
На объекте А установлен циркуляционный насос европейского производства, модель устаревшая.
Производитель больше не поставляет в РФ.

Найди аналоги российского производства с параметрами:
- Производительность: до 8 м³/ч
- Напор: до 6 м
- Монтажная длина: 180 мм
- Тип ротора: мокрый
- Питание: 1×230 В

Для каждого аналога укажи:
- Производитель и модель
- Примерную цену (ориентировочно)
- Отличия от оригинала
Result: list of analogs without revealing the facility, original supplier, or procurement prices. Safe for the cloud.

2. De-identified Price Benchmarking

Need to benchmark construction work prices but can't share estimate details. Use relative figures and general descriptions.

Prompt example (de-identified)
Получено КП на монтаж системы вентиляции в офисном здании.
Площадь: 2000 м², 4 этажа.
Субподрядчик назвал цену (только монтаж, без материалов).

Сделай рыночный бенчмаркинг по Московскому региону, 2025 год:
- Монтаж приточно-вытяжной системы с рекуперацией
- Примерно 8000 м² воздуховодов
- 20 вентиляционных установок
- Автоматика и диспетчеризация

Укажи диапазон рыночных цен (нижняя/средняя/верхняя граница).
Без конкретных сумм из моего КП — только ориентиры.

3. General Technical Specifications

Need a standard TS for a typical construction element. De-identify the object and generate in the cloud, then adapt on-premise.

Prompt example (de-identified)
Подготовь техническое задание на проектирование многофункционального здания.

Общие параметры (без адреса и конкретных бюджетов):
- Площадь участка: 1–2 га
- Площадь застройки: 8000–10000 м²
- Этажность: 2 этажа + подвал
- Назначение: торговые площади, склад, парковка
- Климатический район: III-B (средняя полоса)
- Сейсмичность: 6 баллов
- Энергоэффективность: класс B

ТЗ должно включать:
1. Общие положения
2. Состав проектной документации
3. Требования к конструктивным решениям
4. Требования к инженерным системам
5. Сроки и этапы
6. Порядок согласования и приёмки

Укажи, какие разделы нужно дополнить конкретными данными внутри компании.

Request to Developers for De-identification Automation

If construction specialists frequently de-identify documents manually — this can be automated. Here's a template request for the IT team.

Developer request template
Задача: создать скрипт/приложение для обезличивания 
строительных документов перед отправкой в облачные LLM.

Вход: файл (PDF, Word, Excel) со сметой, КС-2, или техническим описанием.
Выход: тот же файл с заменёнными данными.

Правила замены:
1. Названия объектов → "Объект А", "Объект Б"
2. Названия подрядчиков → "Подрядчик А", "Подрядчик Б"
3. Суммы → относительные ("базовая сумма", "+15%", "-20%")
4. Объёмы → "небольшой/средний/крупный объём"
5. Адреса и координаты → удалить полностью
6. Номера договоров → "Договор N"
7. Даты → относительные ("в текущем квартале", "до конца года")

Дополнительно: проверка — что в выходном файле 
не осталось оригинальных данных (поиск по ключевым словам).

Интеграция: drag-and-drop файл → получить обезличенную версию 
за 5 секунд. Сохранение истории обезличиваний.

Приоритет: высокий (используется ежедневно 3–5 инженерами).
💡 Tip: even if IT cannot build a full application, you can start with a simple Python script. It will replace 80% of manual work. Then improve it.

Knowledge Check

Question 1: What from the list CANNOT be sent to the cloud even after de-identification?

General equipment parameters without brand names
Specific penalty clauses from an active subcontract
"Price above market by 10%"

Question 2: What is the first step of construction de-identification?

Remove all dates
Replace facility names with "Object A", "Object B"
Remove all numbers from the document

Question 3: How do you check if a construction document is de-identified enough?

Send it to the cloud and see if the system blocks it
Show it to a colleague — do they understand the gist but not know the facility?
Remove all numbers and names — that's enough

Question 4: What should you do if engineers constantly de-identify documents manually?

Prepare a request to developers for script-based automation
Continue manually — it's more reliable
Send originals to the cloud — it's faster
