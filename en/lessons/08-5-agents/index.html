8.5 Agent Scenarios for Procurement

⏱ 12 min · how agents automate procurement processes
How is an agent different from a language model?
An LLM answers single requests. An agent works cyclically: it sets tasks itself, calls tools, gets results, and decides what to do next. An agent can visit a website, download a file, send an email — without human involvement at each step.

More about agents — Level 4: Agents and Orchestration.

Scenario 1: Tender Monitoring Agent (n8n + LLM)

Task: daily check of government and commercial tenders, filter by keywords, send a brief digest to the procurement specialist.

Agent Architecture

[n8n Cron: daily at 9:00]
↓
[HTTP Request: zakupki.gov.ru / customer API]
↓
[LLM Node: filter by keywords, assess relevance]
↓
[Telegram / Email: digest "5 tenders for today"]
↓
[Google Sheets: record in registry for analytics]

What the agent does

  • Downloads XML/JSON from the government procurement platform
  • LLM reads lot descriptions, compares with the procurement specialist's profile
  • Assesses relevance on a 1–10 scale
  • Sends only tenders with a score ≥7
  • Records in a spreadsheet for effectiveness statistics
Result: the procurement specialist receives a ready digest instead of 2 hours of manual platform browsing. Saves 10 hours per week.

Scenario 2: Supplier Analysis Agent (OpenClaw-style agent)

Task: when a request for a new supplier comes in — automatically collect public information and prepare a due diligence profile.

Agent Architecture

[Request in system: company name, TIN]
↓
[OpenClaw Agent: parallel calls]
├─→ [Browser: company website → extract activity, contacts]
├─→ [API: Unified State Register → check status, founders]
├─→ [API: SPARK/Contour → financial indicators]
└─→ [Search: news, court cases]
↓
[LLM On-premise: compile into unified profile]
↓
[PDF report in folder + notification to procurement specialist]

Perimeter Security

  • Public data collection — external perimeter (browser, API)
  • Profile compilation, risk assessment — on-premise LLM
  • Admission decision — human (human-in-the-loop)
Important: the very fact of checking a supplier and its results is internal information. The profile is prepared on-premise, even if data is collected from public sources.

Scenario 3: Quotation Comparison Agent (Hybrid)

Task: receive quotations from 3+ suppliers, structure, compare, identify hidden risks, prepare a recommendation.

Agent Architecture

[Email integration: new email with subject "Quotation"]
↓
[Agent: extract attachments (PDF, Excel, Word)]
↓
[On-premise LLM: extract parameters from quotations]
├─ Price, lead times, payment terms
├─ Warranties, penalties, force majeure
└─ Hidden conditions (auto-renewal, sole arbitration)
↓
[LLM: comparison table + SWOT for each quotation]
↓
[Notification to procurement specialist: "Quotations ready for comparison"]

Key Feature

The agent works inside the perimeter: receives emails, processes documents, does not send quotation content outside. The LLM analyzes conditions without seeing competitor names during comparison (if additional confidentiality is required).

Result: comparison of 5 quotations in 15 minutes instead of 3–4 hours of manual analysis. The agent doesn't miss fine print and hidden conditions.
