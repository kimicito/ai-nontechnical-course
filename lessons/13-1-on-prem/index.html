Уровень 13 — ТОиР

13.1 Внутренние задачи ТОиР

⏱ 20 мин · для инженеров ТОиР и начальников цехов
Закрытый контур (on-prem)
Все задачи этого урока работают с реальными данными оборудования, дефектными ведомостями, планами ППР, бюджетами. Используйте внутреннюю модель или локальный LLM.

Почему on-prem критичен для ТОиР

Техническое обслуживание и ремонт оперирует чувствительными данными: состояние оборудования, история отказов, планы ремонтов, запасные части, бюджеты. Передача такой информации во внешние сервисы создаёт риски для конкурентов и регуляторов.

Когда on-prem обязателен:
  • Дефектные ведомости и акты осмотра с реальными данными
  • Root-cause анализ (RCA) отказов оборудования
  • Расчёт MTBF, MTTR, коэффициента готовности
  • Составление планов ППР (планово-предупредительных ремонтов)
  • Бюджетирование ТОиР с реальными цифрами
  • Оценка запасных частей и складских остатков
  • Анализ эффективности оборудования (OEE)
  • Подготовка ТЗ на капитальный ремонт
  • Внутренние инструкции по обслуживанию
  • Претензии поставщикам оборудования

1. Дефектные ведомости и акты осмотра

Формирование технических заключений по результатам осмотра — структурированный текст.

Пример промпта (on-prem)
Подготовь дефектную ведомость на [УКАЖИТЕ ОБОРУДОВАНИЕ]:

Исходные данные:
- Тип оборудования: [УКАЖИТЕ]
- Инвентарный номер: [УКАЖИТЕ]
- Дата осмотра: [УКАЖИТЕ]
- Выявленные дефекты: [УКАЖИТЕ]
- Измеренные параметры: [УКАЖИТЕ]

Структура:
1. Общие сведения об оборудовании
2. Описание выявленных дефектов
3. Причины дефектов (предварительный анализ)
4. Рекомендации по ремонту
5. Необходимые запасные части
6. Смета (материалы + работы)
7. Сроки выполнения
8. Ответственные исполнители

Требования: соответствие форме предприятия, техническая точность.

Результат: готовая дефектная ведомость, экономит 2–3 часа.

2. Root-cause анализ (RCA) отказов оборудования

Анализ причин отказа с использованием 5 Why, Ishikawa, FMEA.

Пример промпта
Проведи RCA отказа [УКАЖИТЕ ОБОРУДОВАНИЕ]:

Событие: [УКАЖИТЕ ДАТУ] произошёл отказ [УКАЖИТЕ УЗЕЛ]
Последствия: [УКАЖИТЕ] — простой [УКАЖИТЕ ЧАСОВ], убытки [УКАЖИТЕ]

Метод 1 — 5 Why:
Почему отказал узел? → [ответ]
Почему [ответ]? → [ответ]
... (5 уровней)

Метод 2 — Ishikawa (6M):
- Man: квалификация персонала, соблюдение инструкций
- Machine: состояние оборудования, износ
- Material: качество смазки, запчастей
- Method: соблюдение регламента ТО
- Measurement: точность диагностики
- Milieu: условия эксплуатации

Вывод: корневая причина, КД, ПД, сроки.

Результат: структурированный RCA, экономит 3–4 часа.

3. Расчёт MTBF, MTTR, коэффициента готовности

Статистический анализ надёжности на основе истории отказов.

Пример промпта
Проанализируй надёжность [УКАЖИТЕ ОБОРУДОВАНИЕ] за [УКАЖИТЕ ПЕРИОД]:

Данные:
- Общее время работы: [УКАЖИТЕ] часов
- Количество отказов: [УКАЖИТЕ]
- Время простоя (всего): [УКАЖИТЕ] часов
- Время ремонта (среднее): [УКАЖИТЕ] часов
- Плановые остановки: [УКАЖИТЕ] часов

Рассчитай:
1. MTBF (Mean Time Between Failures)
2. MTTR (Mean Time To Repair)
3. Коэффициент готовности (Availability)
4. OEE (Overall Equipment Effectiveness)
5. Тренд: растёт/падает надёжность vs прошлый период
6. Прогноз: когда ожидать следующий отказ
7. Рекомендации по повышению надёжности

Результат: аналитический отчёт, экономит 2–3 часа.

4. Составление плана ППР

Планово-предупредительные ремонты — оптимизация графика, ресурсов, запчастей.

Пример промпта
Составь план ППР на [УКАЖИТЕ ПЕРИОД] для [УКАЖИТЕ ЦЕХ / ОБОРУДОВАНИЕ]:

Исходные данные:
- Перечень оборудования: [УКАЖИТЕ]
- Интервалы ТО (ТО-1, ТО-2, ТО-3, КР): [УКАЖИТЕ]
- История отказов: [УКАЖИТЕ]
- Доступный персонал: [УКАЖИТЕ] человек
- Бюджет: [УКАЖИТЕ]

Ограничения:
- Нельзя останавливать [УКАЖИТЕ ОБОРУДОВАНИЕ] в [УКАЖИТЕ ПЕРИОД]
- Критическое оборудование: [УКАЖИТЕ]
- Запасные части на складе: [УКАЖИТЕ]

Выход:
1. График ППР (по месяцам)
2. Потребность в запчастях
3. Потребность в персонале
4. Бюджет по месяцам
5. Риски и резервы

Результат: оптимизированный план ППР, экономит 4–5 часов.

5. Бюджетирование ТОиР

Расчёт затрат на ТО и ремонт, сравнение с фактом, прогноз.

Пример промпта
Подготовь бюджет ТОиР на [УКАЖИТЕ ГОД]:

История (факт):
- [прошлый год]: план [УКАЖИТЕ], факт [УКАЖИТЕ], отклонение [УКАЖИТЕ]
- Основные статьи: запчасти, материалы, подрядчики, персонал

План на год:
- ППР (плановые ремонты): [УКАЖИТЕ]
- Внеплановые ремонты (прогноз): [УКАЖИТЕ]
- Капитальный ремонт: [УКАЖИТЕ]
- Модернизация: [УКАЖИТЕ]
- Запасные части (склад): [УКАЖИТЕ]

Расчёт:
1. План бюджета по статьям
2. Сравнение с прошлым годом (+/- %)
3. Резерв на внеплановые ремонты (10–15%)
4. Критические риски (что может увеличить расходы)
5. KPI: стоимость ТОиР на единицу продукции

Результат: обоснованный бюджет, экономит 3–4 часа.

Проверка знаний

Вопрос 1: Почему план ППР — on-prem?

Потому что содержит перечень оборудования и графики остановок
Потому что методология ППР — коммерческая тайна
Только если указывать конкретные даты остановок

Вопрос 2: MTBF — какой контур?

On-prem — история отказов оборудования
Внешний ИИ — формула MTBF общая
Гибрид — формула снаружи, данные внутри

Вопрос 3: Бюджет ТОиР — какой контур?

On-prem — содержит финансовые показатели
Внешний ИИ — структура бюджета общая
Гибрид — структура снаружи, цифры внутри
